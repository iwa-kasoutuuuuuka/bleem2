# bleem2 ブロック JIT 設計メモ (2026-10-15)

## 現状
- インタプリタ (`src/cpu.c`) は約 120 SH-4 サイクル / MIPS 命令。PS1 実速 (約 20-30M 命令/秒) には 5-8 倍不足。
- 旧 `src/jit.c` は 1 命令ごとに関数呼び出しする構造で、しかも SH-4 エンコードが誤っていた (修正済みだが無効)。

## 方針
1. **基本ブロック単位の再コンパイル**: 分岐 (J/JR/JAL/BEQ...) またはブロック長上限 (32 命令) までをまとめて SH-4 コードへ変換し、`cpu->pc` の更新はブロック末尾で 1 回。
2. **レジスタ割り当て**: `cpu->r[]` はメモリ上に置き、ブロック内でよく使う MIPS レジスタを SH-4 の R8-R13 にキャッシュ (ブロック入口でロード、出口/メモリアクセス関数呼び出し前に書き戻し)。最初は「毎命令ロード/ストア」の単純版から始め、正しさを確認してからキャッシュを追加する。
3. **メモリアクセス**: RAM 範囲はインラインで `mem->ram + (addr & 0x1FFFFF)`、それ以外は C 関数 (`mem_read32` 等) を呼ぶスタブ。
4. **例外/割り込み**: ブロック境界でのみ割り込み判定 (`i_stat & i_mask` + SR)。SYSCALL/BREAK/未定義命令はブロックを終了してインタプリタへ戻す (ブロック内に含めない)。
5. **SMC (自己書き換え) 対策**: RAM 書き込み時にそのページ (4KB) のブロックを無効化するビットマップ。OpenBIOS/ゲームのローダがコードを書き込むため必須。
6. **検証モード**: `JIT_VERIFY=1` で各ブロックを JIT 実行後、同じ開始状態からインタプリタで再実行してレジスタ比較。不一致はログ (VMU) へ。
7. **エンコード**: `sh-elf-as` で生成した参照バイト列と比較する単体テスト (`tools/enc_test.s`) を用意し、エミッタの各命令を検証してから使う。

| 命令 | エンコード |
|---|---|
| MOV.L @(R0,R8),R1 | 0x018E (0000nnnnmmmm1110) |
| MOV.L R1,@(R0,R8) | 0x0816 (0000nnnnmmmm0110) |
| MOV.L R8,@-R15 | 0x2F86 |
| MOV.L @R15+,R8 | 0x68F6 |
| STS.L PR,@-R15 / LDS.L @R15+,PR | 0x4F22 / 0x4F26 |
| CMP/GE R2,R1 / CMP/HS / CMP/EQ | 0x3123 / 0x3122 / 0x3120 |
| NEG R1,R1 / EXTS.B / EXTU.B | 0x611B / 0x611E / 0x611C |
| ADD #-8,R15 | 0x7FF8 |
| MOV.L @(disp,PC),Rn | 0xDn01 で P+8 (P は 4 バイト整列) |
| BRA +3 words (リテラル越え) | 0xA003 (target = P_bra + 4 + disp*2) |

## 段階
- Step 1: ALU/ロード・ストア/分岐のみ、レジスタキャッシュ無し、検証モード常時 ON で OpenBIOS ブートが通ること。
- Step 2: レジスタキャッシュ、条件分岐のブロック内直結、リンク (ブロック間ジャンプのパッチ)。
- Step 3: GTE/COP0 命令の対応、インタプリタへのフォールバック最小化。
